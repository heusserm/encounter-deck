# AGENTS.md — EncounterDeck

Working notes for coding agents. Read this before touching the project; it
records the commands that work and the traps that cost time.

**What it is:** a cross-platform (iOS + Android + desktop) app that generates
random 5e-compatible tabletop encounters and shows them as cards. One shared
Kotlin engine, three front ends. Fully offline — no network calls at all.

**Repo:** <https://github.com/heusserm/encounter-deck> (public)
**Location:** `~/Code/EncounterDeck`
**App Store:** `com.encounterdeck.app`, $0.99, Team `A69JRS6V57`

---

## Layout

```
engine/    Pure Kotlin generator (JVM + Android + iOS). Framework-free and
           heavily unit-tested. Reused as-is by both the backend and the app —
           nothing gets rewritten. Keep it dependency-free.
backend/   Ktor `GET /generate` -> JSON. NOT used by the app, which calls the
           engine in-process. Kept for eventual cloud sync.
app/       Compose Multiplatform UI: androidMain / iosMain / desktopMain.
iosApp/    Xcode wrapper, generated by XcodeGen from project.yml.
scripts/   gen_seed.py regenerates engine/.../SeedMonsters.kt from the public
           5e-database. gen_art.py regenerates app/.../MonsterArt.kt, the
           monster-id-to-drawing map. monsters.json is a gitignored cache.
```

The app has two tabs: the encounter generator and a bestiary that browses,
autocompletes and searches the same bundled monsters. Bestiary search has two
scopes -- name only, or the whole record -- because "poison" matches 75 monsters
by damage type and 3 by name, and both are things people mean. It is a linear
scan over 334 records (0.2 ms), deliberately not a database: an index would cost
more to load than the scan costs to run, and it would drag a dependency into
`engine/`.

## Commands

Requires **JDK 21**. Android needs the Android SDK; iOS needs Xcode.

```bash
./gradlew :engine:jvmTest :backend:test    # the test suite
./gradlew :app:run                         # desktop app
./gradlew :backend:run                     # optional API, port 8080
./gradlew :app:assembleDebug               # Android APK
cd iosApp && xcodegen generate             # after editing iosApp/project.yml
```

For iOS, open `iosApp/iosApp.xcodeproj` in Xcode and Run. The build compiles
the shared Kotlin framework automatically via a pre-build script phase.

## Shipping a build to the App Store

**This is not Flutter.** It needs an explicit two-step archive then export, and
plain `xcodebuild` does not pass `-allowProvisioningUpdates` for you.

```bash
# 1. bump iosApp/iosApp/Info.plist first — see the trap below
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp \
  -configuration Release -destination "generic/platform=iOS" \
  -archivePath build/archive/EncounterDeck.xcarchive archive

xcodebuild -exportArchive \
  -archivePath build/archive/EncounterDeck.xcarchive \
  -exportOptionsPlist ~/Code/AppStoreListings/tools/exportOptions.plist \
  -exportPath ~/Code/AppStoreBuilds/export-<version> \
  -allowProvisioningUpdates
```

The export options use `method: app-store-connect`. Upload the resulting `.ipa`
with **Transporter** (`/Applications/Transporter.app`), or `xcrun altool` with
an app-specific password. The Apple ID is recorded in
`~/Code/AppStoreListings/STATUS.md`, deliberately not repeated in a public repo.

## Traps

**Duplicate build numbers are rejected outright.** Apple refuses a re-upload
with a `CFBundleVersion` that already reached App Store Connect. Bump it in
`iosApp/iosApp/Info.plist` — there is **no `MARKETING_VERSION` in the
pbxproj**, so this is a hand edit.

**No `.xcarchive` is kept on disk.** A new `.ipa` always means a fresh archive;
there is nothing to re-export from.

**Screenshots never live in this repo.** They belong in
`~/Code/AppStoreScreenshots/<size>/encounterdeck_<device>_<screen>.png`.

**Transporter shows a blank icon thumbnail** even when the icon is correct.
That is not a signal — verify with `unzip` + `PlistBuddy` instead.

**`Scaffold` already supplies the system-bar insets.** It hands each screen a
`padding` value; a screen that also calls `safeContentPadding()` insets twice
and leaves a dead band under the status bar. This was live for a while and is
easy to reintroduce when adding a tab.

**Keep `engine/` framework-free.** It is compiled for JVM, Android and iOS and
consumed unchanged by the backend and the app. Adding a dependency there costs
you on three platforms.

**SRD 5.1 content only** (CC BY 4.0, Wizards of the Coast). No Product
Identity, no closed or edition-specific content. The attribution is a license
requirement and ships on **every screen showing SRD-derived content** — the
encounter card, the bestiary list, and the monster detail view — via the single
`SrdNotice` composable. Add a screen that shows monster data, add the notice.
On screen it is one line that opens `AboutDialog`; CC-BY-4.0 3(a)(2) allows the
required text to sit behind a link, and the full six lines inline left the
encounter card a strip on a phone. Shortening it is fine, dropping the link is
not.
It also states that the material was modified, which CC-BY-4.0 3(a)(1)(B)
requires because `gen_seed.py` abridges stat blocks, reconstructs hit dice, and
invents the location tags. Do not remove or reword it without reading the
LICENSE section of README.md.

**Bundled art is a separate licence story.** `app/src/commonMain/composeResources/`
holds 65 public-domain/CC0 drawings; ART.md records each one. None requires
attribution, which is why the app credits no artist — keep it that way, because
adding a CC-BY image would oblige a second notice. Regenerate the id-to-image
map with `python3 scripts/gen_art.py`; it carries an explicit reject list with
reasons, so do not "fix" a missing monster by deleting that list.
